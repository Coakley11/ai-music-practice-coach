# Slice 2 audit and contract

Baselines: Music f125fa935d67058e48d1e9d5d2772e86f9749212; Command Center a5d08e14d3f36d60a2ecb13b05eb7a15e5a741ad.

Music remains authoritative. Key Cycling stores per-owner enabled/status, base_practice_key, start_cycle_key and current_playback_key; temporary playback projection does not write the saved key. Catalog/Custom/Composition are separate owners; Creative-local SBI, Mission and generated Jam owners are intentionally outside this slice. The owner canonical resolver supplies the Backing activity key. Source-prefix validation rejects mixed owner snapshots.

Backing has explicit STOPPED/PLAYING/PAUSED intent and a generation counter. The play-session override bag has stable source identity independent of BPM/style/meter/scope/loops. Pause/resume and new generations therefore cannot define practice activity identity. Direction/interval/key settings can wait for Play; arrangement changes regenerate current audio while transport permission still controls sounding. WAV generation, prefetch, seek, reruns and automatic key transitions are mechanics, not activities. The old backing-start hook was at WAV generation and has been removed from that path.

Schema: existing practice_session_started, activity_schema_version=2, practice_context_id (UUID), monotonic practice_context_revision, workspace, source_type/source_id, song, instrument, practice_key, practice_mode, cumulative backing_active/key_cycling_active, first observed cycle start key and optional sounding-key snapshot. Resume carries source identity and canonical display_key, never a sounding key. Context boundaries: workspace/source/song/instrument/canonical key change; browser session refresh can begin another context. Mode and transport/configuration changes do not create contexts.

Each context emits an initial snapshot and at most two semantic upgrades. Raw records remain append-only; Command Center chooses the highest context revision (timestamp breaks ties) per context plus workspace/source/instrument/key identity before its existing grouping. The snapshots are cumulative, so a stop cannot erase earlier work. New contexts retain factual summaries rather than generic run-count rollups. Legacy events retain legacy grouping.

No exact distinct-key count or duration is claimed. A playable player mount with explicit playback permission is the observation boundary; this measures playback initiation, not acoustic confirmation or user attention. Browser autoplay rejection/device silence cannot be detected by this slice. First cycle key is observed configuration, not a measured completed pass. Optional authoritative style/BPM and interval/direction are omitted to keep this version conservative.

Backing activity persistence runs in a single worker using only copied event/payload data. It never receives live Streamlit state, never persists Music local_state, and cannot throw into player code. Existing cloud -> local -> JSON fallback is retained. Reporting is best effort; process termination or all stores failing can lose activity. No cross-refresh activity identity or durable telemetry outbox is introduced.

Resume: new context payloads are deferred until catalog/document bootstrap, dispatched through activate_active_song_by_pick_key, and rejected when activation fails rather than silently claiming a stale song. The canonical key is queued with pick-scoped Practice Key ownership. Transport is stopped, prepared cycling audio is invalidated, and cycling/autoplay/restart requests are cleared. No audio is started and no transport internals are restored. Existing typed payload links are recognized as well as scalar links.

Validation: focused tests cover Catalog/Custom/Composition, canonical vs temporary keys, five automatic-key observations, repeated reruns, Play/Pause/Resume/Stop, simulated config changes, cycling stop/restart, owner/key/instrument switch, optional fields, duplicate deliveries, fallback and unavailable integration, deferred Resume, missing-source rejection, and async persistence. Existing cycle/transport suites provide real state-machine regression coverage. UI harness qa_slice2_activity.py loads the exact production Activity functions and CSS through AST, avoiding account/bootstrap/cloud IO; fixtures are synthetic. It is a section-level render check, not a full-app audio acceptance run.
