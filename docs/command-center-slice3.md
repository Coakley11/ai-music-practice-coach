# Music → Command Center Slice 3: audit and candidate contract

Baselines: Music d459e0a5329c27c920e31dc1f1c469319a54e637; Command Center 18e39c6996da7d70d82cf53990ce80fe8b752acc. Both were fetched and verified before work. Local candidates only.

## Audit

Missions are constraint-based practice tools. PRACTICE_MISSIONS contains the authoritative names. Explicit example generation stores an artifact, difficulty/idea state and musical/ownership context; Backing and recording handoffs are separate. There is no authoritative completed state, Mark Complete action, or completion lifecycle. Analysis “mission completion” is a scoring goal, not a lifecycle transition. Existing traces and persisted example artifacts are not Command Center accomplishment events. This slice must never fabricate completion or equate generation with mastery.

Song-Aware Coaching stores a versioned song_coach_session (CoachState): owner identity, musical fingerprint, draft/built selection, plan id, instrument, challenge/check state, examples and loop/handoff settings. The verified SongCoachContext binds Catalog/Custom/Composition identity and concert key to the owner's actual chart. It rejects stale or unavailable charts. The plan cache and widgets are transient. Context, plan selection and user progress belong to Music; diagnostic values are not authority. A successful Build My Coaching Plan is the meaningful session-use boundary. Challenge navigation, self-checks, repeated builds and examples must not each create cards.

Composition documents have stable UUIDs, title, owned global key/tempo/meter, ordered sections, accepted musical content, lyrics, workflow and integration metadata. composer_active_document is the editing document, not necessarily the global active song. save_document_to_library upserts the canonical UUID library mirrored in composition_workspace_state; automatic edits checkpoint frequently. The explicit Save to Composition Library UI verifies actual disk/cloud save outcomes. Only that confirmed explicit transaction is reported. A default/draft document appearing is not an authoritative creation milestone. Lyric alignment/melody acceptance and automatic edits remain outside this smallest slice.

Global source authority remains in the existing source_session_state / workflow_musical_authority / songs modules. Coaching reads the verified source-owned context; Mission reporting reads that same owner's document identity and the existing underlying-song concert Practice Key, independent of the intentionally collapsed Mission map. Composition reporting reads the document actually saved, even if Catalog/Custom remains the global active song. Reporting never activates a source, imports a document, or writes a local-state snapshot to the suite activity store.

## Events, privacy and identity

Schema version 3 adds immutable progress snapshots: mission_started, song_coaching_used, composition_saved. Metadata is allowlisted: workspace, source type/id, title, instrument/concert key where meaningful, actual mission name or enumerated coaching focus, save/update designation, opaque progress_activity_id and optional small Resume envelope.

Mission starts are emitted after successful explicit example generation, once per mission/source/instrument/canonical-key context in a browser session. Coaching use is emitted after a successful explicit plan build, once per source/instrument/canonical-key context in a browser session; later focus changes do not generate a card per action. These session IDs intentionally do not claim elapsed time, completion, mastery, or exact practice counts. A fresh browser session can represent new use.

Composition saves use a stable opaque digest of workspace, UUID and semantic content. The content is hashed locally; no lyrics, note arrays, prompts, recordings, analyses or documents cross into the event. Timestamp, workflow navigation and AI draft intents do not change the digest. Unchanged explicit saves are suppressed in-session; duplicate/retried delivery after refresh collapses in Command Center by workspace/source/event/id. A richer updated designation cannot be downgraded by a saved retry. Automatic saves/rendering emit nothing. Reverting to identical previously reported content collapses to the same milestone; there is no artificial edit counter.

All reporting uses the existing single-worker detached activity path with copied metadata, local_state=None and guarded exceptions. This remains best effort: all stores failing can lose an event, with no durable retry outbox. Reporting failure does not alter the underlying action outcome.

## Resume

Verified Catalog Mission and Coaching Resume extend the Slice 2 deferred bootstrap and canonical owner dispatcher. They restore source, instrument and owned canonical concert key, select the supported Creative destination, clear playback/cycling restart requests and explicitly hold autoplay false. Current canonical source title outranks the older event label. Mission Resume selects the actual mission but does not mark completion or regenerate an example. Coaching Resume delegates existing plan reconciliation to Music; no temporary state or plan is embedded in the link.

Custom and Composition progress cards deliberately have no Resume action; their cold-source restoration is not verified. Composition cards always omit Resume. Real cold-session testing could not resolve the saved Composition document reliably through the current bootstrap/library hydration path. A seeded unit-test library was insufficient evidence. The experimental Composition URL support was removed; the renderer also refuses Composition save-card links from older experimental payloads. This follows the requested preference for no action over a wrong source/destination. The UUID remains observer metadata, not Command Center-owned document state. Later Backing-filter hydration also respects stopped/paused transport when copying autoplay flags, so a saved true flag cannot survive this restore.

## Verification plan

Use Playwright Chromium against both real local apps with isolated storage/cloud disabled.
